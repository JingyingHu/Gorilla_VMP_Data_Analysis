## Understand your data (data columns guide)
**Gorilla data columns guide**
  - [Questionnaire and Task columns](https://support.gorilla.sc/support/publishing-and-open-science/data-analysis#datacolumns)
     - **Participant Private ID**: A unique anonymous ID automatically generated by Gorilla representing this participant.
     - **Task Name**: The name of the current task
     - **Response Type**: (filter the data data you're most interested in)
     - **Key**: (filter the data you're most interested in)
     - **Response**: (filter the data you're most interested in)
   - [Eye tracking data columns](https://support.gorilla.sc/support/tools/task-builder-2/eye-tracking#eyetrackinganalysis)
     - **Stilimi **~ (link to the row id of the spreadsheet that you uploadeed when you set up the experiment)
          - **Spreadsheet Index**:  The current row number in the task spreadsheet minus 1   
     - **Object locations**
          - **'Zone Name'**: Name of the object (e.g., images in the screen)
          - **'Zone X Normalised'** and **'Zone Y Normalised’**: Coordinate of **the left and top edges** of the object in normalised space (i.e. as a proportion of the Gorilla stage). 0,0 is at the bottom-left of the stage.0.5,0.5 will always be the centre of the stage, regardless of how big the stage is.
          - **'Zone W Normalised'** and **'Zone H Normalised'**：**Width and height** of the object in normalised space (i.e. as a proportion of the Gorilla stage).
     - **Prediction row**, represents Webgazer’s prediction of where the participant is looking on the screen.
          - **'Predicted Gaze X Normalised’ & ‘Predicted Gaze Y Normalised’**: prediction locations normalised as a proportion of the Gorilla stage. 0,0 is at the bottom-left of the stage.
          - **'Timestamp'**: the current absolute timestamp in Unix time for recording each prediction, without any adjustment for frame rendering. A prediction is requested every 10ms (100Hz), but the recorded timestamp may be slightly different. WebGazer.js does not provide a consistent sampling rate, as there is a slight variable delay in generating predictions – based on the participant’s computer and browser power.
          - **'Elapsed'**: It represents the time that has passed in milliseconds since eye tracking started on this screen.
           


## From Gorilla to Tidy Data
- **read in  the raw data**: `read.csv()` function or `read.xlsx()` function
- **filter out the relevant data**
   * select the relevant **rows**: `filter()` function
   * keep the revevant **columns**:  `select()` function
   * rename colnames: `rename(new name = old name)` function
   * add new columns: `mutate()` function
   ```r
    final <- task %>%
     filter(`Component Name` == "Keyboard Response") %>%
     select(`Participant Private ID`,
            `Participant OS`,
            `Participant Device`,
            `UTC Date and Time`,
            `Spreadsheet: Answer`,
            `Response`,
            `Reaction Time`) %>%
      mutate(group = "L2") %>%
      rename(NumberResponse = Response)
-  **combine different dataframes**:
   * by row: `rbind()` function, or `dplyr::bind_rows()`function 
   * by columns （especially merging different tasks data based on participant id):  `_join()` function (e.g., [left_join() , inner_join() , right_join() , full_join()](https://psyteachr.github.io/msc-data-skills/joins.html))
- **reshape the data**
    * from wide to long: `pivot_longer()`function
    * from long to wide: `pivot_wider()` function
   ``` r
   items_back <- participant_items %>% pivot_longer(cols = -ID,        #use all columns apart from the ID column (cols = -ID)
                                                    names_to = "item", #he column names should go back to an item column
                                                    values_to = "acc") #the values should go in an acc column

## Toolboxes for eye-tracking data analysis
- **R: ‘eyetrackingR’**
  - Area of Interest (AOI) based tracking
  - Various tools available for: Window analysis (i.e. in a certain window of time where did people look), Growth Curve Analysis (i.e. modelling timecourse of attention towards targets), Cluster analysis (identify spatio-temporal clusters of fixations in your data)
  - Tutorial for reading in data: http://www.eyetracking-r.com/vignettes/preparing_your_data
  - Note: you have to use the ‘add_aoi’ function to convert X,Y data into AOI data

- **R: 'VWPre'**
   -  a new tool for data preprocessing, and generalized additive mixed modeling (GAMM), a relatively new approach for nonlinear time-series analysis (using mgcv and itsadug)
   -  Porretta, V., Kyröläinen, A. J., Van Rij, J., & Järvikivi, J. (2017, May). [Visual world paradigm data: From preprocessing to nonlinear time-course analysis](https://www.researchgate.net/publication/318101004_Visual_World_Paradigm_Data_From_Preprocessing_to_Nonlinear_Time-Course_Analysis). In International conference on intelligent decision technologies (pp. 268-277). Cham: Springer International Publishing.
 
- **R: 'stats.VWP'**: https://github.com/aineito/stats.VWP
